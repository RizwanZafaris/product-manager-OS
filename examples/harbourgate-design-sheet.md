# Harbourgate Design Sheet: the data behind the experience-design examples

Fills no template. This file extends [harbourgate-journey.md](harbourgate-journey.md) and never contradicts it. It is the supplementary data sheet for the experience-design examples: the heuristic evaluation and design review record of the guest checkout redesign, and the component spec and DESIGN.md that describe the system those examples review. Everything is invented: Harbourgate, Quay, Kestrel and every person are the journey's fiction, and every number, hex value, date and pound here is ILLUSTRATIVE, chosen so the design files reconcile with the sixteen journey artifacts and with the read-only coverage sheet. It is never to be quoted as a benchmark or copied as a target. See the [examples index](README.md).

**Owner:** Ines Castellanos, Design Lead, owner of the deferred guest checkout redesign · **Date:** 2026-10-20 · **Extends:** [harbourgate-journey.md](harbourgate-journey.md) · **Seed:** the redesign was named as out of scope in the seed and carried forward as a deferred item; see the journey's "Inherited from the seed" section · **Gates:** [os/STAGE-GATES.md](../os/STAGE-GATES.md)

## Rules for every design file

- **The journey wins.** Where this sheet and [harbourgate-journey.md](harbourgate-journey.md) could be read two ways, the journey's reading holds. No design file moves a journey date, owner, outcome, score or gate attempt, and no N row is restated here with a different value.
- **Two sources of numbers, nothing else.** A design file cites journey rows by their own ids (N31, BR-004, R2) and this sheet's rows by HD id. Firmness uses the journey's four words: measured, estimate, target, assumption.
- **The prefix is HD.** HD is unused anywhere in the journey, its sixteen artifacts, the coverage sheet or its thirty-one coverage files. The other new identifiers this sheet claims are listed under New identifiers, and each was checked against the journey's identifier tables and the coverage sheet's identifier tables before it was claimed.
- **One evaluator is one evaluator.** A single AI pass through a screen or a prototype, if one is ever run, is logged as exactly one evaluator in any panel here, never as coverage equal to a person. No design file in this set runs one; where a future design file does, this rule still governs it.
- **Regulatory rows carry their caution.** Any row resting on real accessibility law or standards (not on Harbourgate's fiction) is marked "as of 2026-09-10", names a review trigger, and is not legal advice; confirm with counsel before any launch date depends on it.

## Cast additions

Four roles, none named, used across the design files: two product designers on the redesign squad; a UX researcher; the front-end engineer who implemented the payment outcome panel; a QA engineer, distinct from Noor Haddad's QA Lead role, which the journey names for a different purpose. Where a design file needs someone beyond these and the journey's thirteen named people, it uses a role, as the journey and the coverage sheet do.

## Reconciliation notes

These are the places where a careless draft would contradict the journey or the coverage sheet, with the reading every design file follows.

1. **The redesign is the seed's deferred item, run after Gate 6.** The seed's out-of-scope table held the guest checkout redesign; the journey never reopens it. This design pass is a new loop pass that opens after the journey's Gate 6 PERSIST (2026-10-14), so every date in this sheet falls on or after 2026-10-19, and the coverage sheet's reconciliation note 7 ("no visible change for shoppers" for the Quay journey) stays true: the redesign changes the guest checkout's screens, not Quay's payment path. The design review record's own decision date is 2026-11-11, which is the redesign pass's Gate-3-equivalent review, not a reuse of the journey's Gate 3 date of 2026-04-10; the record's status line "Approved at Gate 3 with conditions, 2026-11-11" refers to this redesign pass's own review.
2. **The kiosk fallback is N31 and BR-004 exactly.** "Pay at the till" within 10 seconds, basket held 30 minutes. No design file invents a different kiosk timeout or hold window; where a finding is about that fallback, it is about the screen and its copy, never about the numbers.
3. **Payment outcome codes follow [harbourgate-api-contract.md](harbourgate-api-contract.md).** That file is a journey artifact, read live from its path in the examples directory, per the design-writer contract. This sheet does not restate its outcome codes; the component spec cites them directly from that file, in backticks, never as a link.
4. **Kestrel's hosted card fields are third-party content.** The panel and the design tokens style Harbourgate's own surfaces around them; Kestrel's hosted fields and step-up challenge render in their own frame and are assessed as a partial-conformance item, never marked as a Harbourgate defect to fix.
5. **No design file records a stage-gate outcome the journey has not recorded.** The journey's Gate 3 closed on 2026-04-10 for Quay and is never reopened here. The design review record's decision is the redesign pass's own review, signed by the names this sheet carries, and it is not entered as a new Gate 3 attempt in the journey's own gate-attempts table.
