# Coverage Sheet: Sahulat Bill Pay, the extension

Fills no template: this file extends the data sheet in [sahulat-journey.md](sahulat-journey.md), which it never contradicts, and is the index and data sheet for the Sahulat coverage files named in the artifact map below, each of which fills one template or runs one worksheet. Everything here is invented and every number is ILLUSTRATIVE: Sahulat, its people, agents, customers, billers, bank, aggregator and telco are fiction, and the values below were chosen so that the coverage files agree with the fourteen journey artifacts and with each other, not to describe any real wallet, market or regulator. ## What this sheet adds

The journey runs from the trigger on 2026-01-12 to the Gate 6 PIVOT on 2026-08-28. The coverage files sit in three places around it, and none of them changes a fact the journey already states.

- **Before the trigger, 2025-09-01 to 2025-12-31.** Faisal Mirza wrote the scorecard for the company's first product manager before the req opened; the hire was Hira Baig, who started on 2025-12-01. Her first 90 days run to 2026-02-28, so the trigger on 2026-01-12 is her day 43 and Gate 1 attempt 2 on 2026-02-27 is her day 89. The one reversible change she made in month one was asking Naveed Akhtar to add the BILL-ASK tag to the agent helpline, which is where N13's 412 calls came from.
- **Inside the journey, 2026-02-16 to 2026-05-20.** Worksheets and plans the fourteen artifacts never needed to name: an empathy map and a journey map of Shazia from the pass-1 sessions, a PESTLE scan and an Ansoff matrix feeding the vision, a market sizing between the vision and the north star sheet, an impact map and a story map at the start of DEFINE, a usability round on the paper USSD menu before Gate 3, and the MoSCoW sheet behind D5.
- **After the pivot, 2026-09-01 to 2026-09-29.** The DISCOVER pass that D8 opened on 2026-09-07 with Rafiq at the centre, plus the OPERATE reads Sara Lodhi prepared for the first recurring metrics review on 2026-09-21. None of these files closes a gate: Gate 1 of the second pass is not scheduled. Open: Hira Baig.

No cast addition is needed. Every role in the coverage files is filled by someone in the journey's cast table; where a file needs a person the cast does not name (an interviewer at a hiring loop, a squad engineer building a prototype), it names the role, never a new name.

## Conventions the coverage files share

- Everything in the journey's conventions list still holds: PKR with the unit, dates as YYYY-MM-DD, "percent" written out, ids never renumbered, "Open:" followed by an owner rather than a blank.
- New number rows use the prefix CN, CN1 to CN38. The journey's N rows keep their meaning; a coverage file cites N and CN rows side by side.
- New participant codes continue the journey's series: agents A-07 to A-17, customers C-09 to C-13, sessions INT-015 to INT-020. Usability participants and hiring candidates get their own prefixes (UC, UA, CAND) so a usability task or a candidate is never read as an interview. No names appear in any note, and no candidate name appears in the hiring scorecard.
- Worksheet ids that would collide with journey ids are prefixed here: assumptions are AS-1 to AS-7 (not D1, which is a decision), desired outcomes OUT-1 to OUT-5 (not O1, which is the one-pager objective), usability tasks TK-1 to TK-5 (not T1, which is a theme), usability findings UF-1 to UF-4, sprint questions SQ1 and SQ2, and sprint grid columns carry participant codes rather than P1 to P5, which are personas.
- Per-story estimates stay Open with Zainab Qureshi, exactly as the story register says: this squad does not point stories. Any file that needs effort uses engineer-weeks per slice from the sprint log (CN rows below), never a size per story.
