# Edge-Case Register: Harbourgate Quay checkout payment flow

Fills [templates/delivery/edge-cases.md](../templates/delivery/edge-cases.md). Everything here is invented: Harbourgate is a fictional mid-market retailer, Quay, Kestrel, Marlowe and Tidewater are fictional, every person is the journey's fictional cast, and every number, date, amount, rate and identifier is ILLUSTRATIVE, taken from [harbourgate-journey.md](harbourgate-journey.md) (the canonical data sheet) or its supplement [harbourgate-coverage-sheet.md](harbourgate-coverage-sheet.md), never to be quoted as a benchmark. - [x] Duplicates, retries, and double submission

- [x] Localization and encoding (long names, non-Latin scripts, emoji, RTL text; walk [localisation-rtl-checklist.md](../templates/architecture/localisation-rtl-checklist.md) for a bidi UI): considered, zero rows. The payment step's screens are existing components whose provider changed, not a new surface ([harbourgate-coverage-sheet.md](harbourgate-coverage-sheet.md) reconciliation note 7), and the localisation waiver sits in the NFR with a revisit date, so no edge case belongs here that the checklist does not already own.
- [x] Network failure, timeout, and partial failure mid-transaction
- [x] Malicious input (injection, oversized payloads, unexpected content types)
- [x] Volume (the 10x day, the empty account, the account with years of history)
- [x] For AI features: refusal, escalation, and never-invent behavior (see [guardrails](../templates/ai/guardrails.md) and [red-team review](../templates/ai/red-team-review.md)): considered, zero rows. No model is present on the payment path, which is why the regulated overlay did not fire ([harbourgate-compliance-impact-assessment.md](harbourgate-compliance-impact-assessment.md)).
