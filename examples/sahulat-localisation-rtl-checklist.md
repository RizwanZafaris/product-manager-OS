# Localisation and RTL Checklist: Sahulat Bill Pay, the second-pass agent-handset app flow

Fills [templates/architecture/localisation-rtl-checklist.md](../templates/architecture/localisation-rtl-checklist.md). Everything here is invented: Sahulat is a fictional mobile-money wallet in Pakistan run by a fictional licensed electronic-money institution, its people, agents, customers, billers, bank, aggregator and telco are fiction, and every number, name and date is ILLUSTRATIVE, drawn from the shared data sheet in the [Sahulat journey](sahulat-journey.md) rather than from any real wallet or market. See the [examples index](README.md).

## 5. Numbers, dates, calendars and currency

| Check | How to verify | Evidence | Result | Owner |
|---|---|---|---|---|
| The digit family rendered matches the locale's actual default (European, Arabic-Indic, or Extended Arabic-Indic), not assumed from the language code | Render a PKR amount (e.g., PKR 2,400, N23) and a date in the target locale; compare against CLDR ur-PK locale data pulled from the platform's ICU library at runtime | ICU debug output showing `numberingSystem: latn` for ur-PK; rendered amount displays European digits by default, matching CLDR's `ur-PK` default rather than the assumption the pass-1 team started from; cross-checked against CLDR JSON for ur-PK (SD1) | Pass | Zainab Qureshi |
| A user can override the digit family where the locale supports more than one convention | Navigate to Settings > Display > Number format; confirm the toggle between the CLDR default (European digits) and Extended Arabic-Indic digits persists across app restarts | Settings screen screenshot with both options visible; preference persisted in SharedPreferences XML after toggle and restart (SD10) | Pass | Mariam Gill |
| The calendar rendered matches the locale's default (for example Solar Hijri for fa-IR), not hardcoded Gregorian | Render a bill due date in Urdu locale; confirm the platform's ICU-backed formatting returns Gregorian (Pakistan's default), not Hijri or any other calendar system | Date formatter output: `due_date_formatted: "2026-11-05"` in Gregorian; no Hijri conversion applied; confirmed against ICU `Calendar.getAvailableCalendars()` for ur-PK (SD1) | Pass | Zainab Qureshi |
| Thousands and decimal separators match the locale (Western vs Eastern Arabic-speaking regions differ) | Render PKR 1,150,000 (N9 scale) and a fractional amount like PKR 12,300.50 (N48) in Urdu locale; confirm separator characters | Formatted output: "1,150,000" and "12,300.50" (thousands separator U+002C COMMA, decimal separator U+002E FULL STOP); matches CLDR ur-PK's `latn` default, not the Arabic-Indic separators (U+066B, U+066C) the team initially assumed from the digit script alone (SD1) | Pass | Zainab Qureshi |
| No date, number or currency format is hand rolled outside the platform's locale formatting library | Grep the codebase for manual string concatenation of date parts, hardcoded thousand-separator characters, or `NumberFormat.getInstance()` bypasses | Static analysis report: zero violations after removing two legacy helpers that formatted amounts with `String.format()` and manual comma insertion; all formatting now routes through `java.text.NumberFormat.getInstance(locale)` (SD4) | Pass | Zainab Qureshi |
