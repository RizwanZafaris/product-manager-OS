**When this is the wrong document.**

- **The model is already pinned and the question is whether it is good enough.** That is [eval-spec.md](eval-spec.md).

## 3. Fully loaded cost per successful task

<!-- Price per token is not cost. A cheap model that needs more retries, fails more
     tasks and makes people fix more of its output can be the most expensive line in
     the table. Count tokens from the eval run's own logs, per model, because
     tokenizers differ and verbosity differs: the same ticket is not the same number
     of tokens on two models. If the vendor discounts cached input, give cached
     tokens their own row at their own price rather than blending them. -->

**The arithmetic, used unchanged for every candidate:**

- Cost per attempt = (input tokens per attempt x input price per token) + (output tokens per attempt x output price per token) + (tool calls per attempt x cost per tool call)
- Attempts per task = 1 + retries per task, averaged over the eval run
- Model cost per task = cost per attempt x attempts per task
- Model cost per successful task = model cost per task / task success rate, where the success rate is the section 2 primary metric
- Review cost per successful task = human minutes the output forces, including time spent reading outputs that were then thrown away, divided by successful tasks, x loaded cost per minute
- Fully loaded cost per successful task = model cost per successful task + review cost per successful task
- Monthly model spend = model cost per task x forecast tasks per month (every task is attempted, so this line uses cost per task, not per success)

## 8. How this choice goes wrong

<!-- Read this table before the comparison runs, not after. Every row is a way the
     file looks complete while the choice it records is not the one the evidence
     supports. If a tell is present, fix it or write it beside the decision; never
     delete the row because it is awkward. -->

| Failure | The tell | What to do |
|---|---|---|
| Picked from a leaderboard | The section 2 score cites a benchmark name, not an eval set version and hash | Re-run every candidate on the team's own set before the decision stands |
| Price per token read as cost | Section 3 stops at the price rows; no retries, no success-rate divisor, no review minutes | Fill every arithmetic row; the divisor alone often reorders the table |
| The incumbent was tuned and the challengers were not | Prompt iterations in section 1 differ by a factor of two or more | Give the challengers more iterations and re-run, or write the bias beside the decision |
| Candidates measured on different cuts | Two columns name different eval set versions or hashes | Re-run on one version; a comparison across cuts compares nothing |
| Latency as an average | Section 4 holds a mean or a p50 and no p95, or the budget was written after the measurement | Set the budget first, measure p95 at peak, from the serving region |
| Vendor terms from a marketing page | A section 5 cell has no document name and date | Find the clause in the signed terms, or mark the cell open with an owner |
| A fallback nobody evaluated | The fallback has no section 2 result, or the degraded mode has no time limit | Run it on the same set; if it fails the floor, write the degraded mode down and have its owner accept it |
| A choice that never comes up again | Section 7 is empty, or every trigger names a team rather than a person | Name a watcher per trigger and put the calendar date in someone's diary |
