# Product Ops Charter: [company or product group]

**Stage:** ALL STAGES (the function serves every stage of the [operating loop](../../os/OPERATING-LOOP.md) and declares no gate of its own)
**Knowledge:** [product operating model assessment](../../frameworks/assessment/product-operating-model-assessment.md), whose deficits name the problems this function is chartered to own
**Skill:** [product-review](../../skills/product-review/SKILL.md) for the review ritual this function keeps healthy; [feedback-synthesis](../../skills/feedback-synthesis/SKILL.md) for the insights pipeline it runs

**What checks this.** This template declares no gate, so a filled copy joins no gate's approval manifest and editing it later stales nothing. That is deliberate: a document revised on a cadence, such as an OKR sheet or an exec update, would otherwise invalidate whichever gate it had been bound to every time it was revised. It is an input to whichever gate is open, and the people who sign that gate decide what to do with it, per [os/STAGE-GATES.md](../../os/STAGE-GATES.md). No tool checks whether what you write is right. This paragraph is generated by `python3 tools/what_checks.py`.

## How this charter fails

| Failure | The tell | What to do |
|---|---|---|
| A project office by another name | The function's main output is a weekly status deck compiled from teams' updates | Status lives in each team's [status report](status-report.md); drop the deck and measure section 6 |
| Gatekeeper of the roadmap | Teams ask product ops for permission to change a priority | Section 3, first two rows: the function brings evidence and runs calendars, it does not decide |
| The dumping ground | The backlog fills with requests that fit no area in section 2 | Those requests go to the reporting line, and the charter is amended or the request declined in writing |
| Tool administration only | Every indicator in section 6 is about licences and access | Re-read section 1: tooling was one of five problems |
| Measured on activity | The quarterly review counts templates written and meetings run | Section 6 indicators only, each read beside its counterweight |
| Process that only grows | No retirement entry two quarters running | Treat it as a missed service level and escalate it as one |
| Decisions owned through templates | A template change quietly adds an approval step nobody agreed | A template change that adds a decision step needs the reporting line's sign-off and section 5's notice period |
