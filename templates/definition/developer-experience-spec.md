<!-- Time to first successful call is the onboarding number you control

## 11. How this spec passes while developers still struggle

| Failure | The tell | What to do |
|---|---|---|
| Time to first call measured from sign-up | The start event is account creation | Move the clock to the first documentation view or sign-up start, and report the earlier drop-off |
| Median of survivors | Time to first call improves while 7-day completion falls | Report both, every time |
| A sandbox that lies | It accepts inputs production rejects, and integrations fail on their first production day | List every difference in section 3; run the contract tests against both |
| Limits set by infrastructure alone | The limit equals the last load test's ceiling and no plan or customer reasoning is written | Write the product reasoning and the raise path |
| Errors written by the framework | Messages read "Bad Request" or name an exception class | Author the first-hour messages in section 7, with links |
| Deprecation by changelog only | Callers learn of a removal when their calls fail | Direct notice to active callers, response headers, per-customer telemetry |
| SDK sprawl | Many languages, several months behind the API | Fewer SDKs, each with an owner and a support window |
| Sign-ups as success | The metric that rose is registered developers | Integrations in production, with a fixed bar |
| The approver forgotten | Security review blocks the first enterprise deal after launch | Fill the approver column in section 1, and section 5's last line, before Gate 2 |
