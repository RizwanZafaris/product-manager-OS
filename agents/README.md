# Agents: the role instruction files

This directory holds identities, not procedures. A file in [skills/](../skills/README.md) says how a piece of work is done, step by step. A file here says who is doing it: what that role may assert, what it must refuse, what it hands on, and the one hard rule that makes its output trustworthy. The distinction earns its keep at the boundaries. The drafting agent may fill a field; the validation agent may not, because a checker that edits becomes an author and then nobody is checking the author. Several agents reach for a worksheet in [frameworks/](../frameworks/README.md) before they touch a template, the architect agent's decision-doors sheet and the estimator agent's estimation sheet among them, because the arithmetic behind a judgment call belongs in one place, not in the agent's head.

One role per run. A run that spans two roles loses the thing the separation was for. The router in [AGENTS.md](../AGENTS.md) names the twelve files and their hard rules; this page says what each one is for and who reaches for it.

| File | The role | Who invokes it |
|---|---|---|
| [research-agent.md](research-agent.md) | Gathers evidence for the DISCOVER set and marks everything it could not verify as an assumption. Its method is the product-analyst skill; this file is the constraints it runs that method under | A user asking for the facts behind a discovery template, or the Conductor handing off a research step from the DISCOVER bank |
| [drafting-agent.md](drafting-agent.md) | Fills exactly one named template per run from supplied evidence. Every field gets a traced value, an `N/A because <reason>`, or an open-field marker with an owner. It never invents a number or a name, and it flags conflicting evidence rather than choosing between sources | A user who has the evidence and wants the first complete draft, or the Conductor handing off template drafting once answers are accepted |
| [validation-agent.md](validation-agent.md) | Checks a draft against two references, the template it claims to instantiate and the gate it feeds, then walks the gate checklist line by line and reports what is missing, malformed, or unowned. It reports; it never rewrites | Before any draft reaches a human reviewer, and before any gate conversation starts |
| [red-team-agent.md](red-team-agent.md) | Attacks the artifact as three hostile readers in turn: the stakeholder hunting the weakest commitment, the auditor pulling the traceability thread, the attacker reading the spec as a map. For model-containing products it also runs the structured pass in [templates/ai/red-team-review.md](../templates/ai/red-team-review.md) | Before Gate 3 and Gate 5, or whenever a document has only ever been read by people who want it to succeed |
| [architect-agent.md](architect-agent.md) | Turns a signed requirement set into architecture options with named trade-offs and drafts the ADR once a choice is made, classifying each decision's reversibility first so only one-way doors get the full record. It never picks the option, challenges every NFR number rather than copying it, and routes cost questions to the estimator agent instead of guessing them | The Conductor handing off a DESIGN step once Gate 2 is signed, or a user who needs options priced before Gate 3 rather than a recommendation dressed as a foregone conclusion |
| [acceptance-agent.md](acceptance-agent.md) | Turns signed acceptance criteria into tests that can fail and reports, criterion by criterion, whether the evidence that they ran actually exists somewhere a reader can open. It never writes "passed"; its five statuses stop short of that word until a human opens the evidence and signs Gate 4 | Before anyone claims Gate 4 is met, or the Conductor handing off a BUILD step that needs an honest gap report instead of a status update |
| [release-manager-agent.md](release-manager-agent.md) | Assembles the go, no-go, or conditional-go packet Gate 5 decides on: the readiness checklist with evidence beside every line, a rollback confirmed as performed rather than described, and release notes cut three ways from one block of launch facts. It recommends; an unowned condition on a conditional go is a no-go in its own accounting | The release owner preparing a launch meeting, or the Conductor handing off the DELIVER step once acceptance evidence and comms drafts exist |
| [analyst-agent.md](analyst-agent.md) | Defines a metric so two people would compute the same value, then reads cohorts and funnels for exactly what the data shows, no further, with a confidence label on every figure. It never invents a number or a baseline, and it names the question a number cannot answer instead of guessing at one | A metrics review that needs its values traced to source systems before Gate 6, or the Conductor handing off an OPERATE step when a metric moved and nobody has said why |
| [growth-agent.md](growth-agent.md) | Names the loop or funnel mechanism behind a metric, locates the leak by number, and ranks an experiment backlog by what each idea would teach if it failed. It proposes; it hands the chosen bet to the experiment-designer skill rather than sizing or running anything itself | A growth plan that needs its next bet chosen from a ranked backlog rather than the loudest idea in the room, or the analyst agent's reading handed off for a mechanism diagnosis |
| [pmm-agent.md](pmm-agent.md) | Works positioning from competitive alternatives forward to a category, then derives messaging, the launch narrative, and sales enablement from it, with every claim tracing to evidence or an acceptance-agent-verified criterion. A claim the product cannot do is reported as a defect, never softened into copy | A launch that needs positioning and a sales one-pager built on what shipped rather than what was pitched, or the release manager agent handing off the narrative once the launch facts are fixed |
| [estimator-agent.md](estimator-agent.md) | Sizes work as a range with a stated confidence and a reference class, never a single number, and walks the same missing-work list every time so compliance review, rollback rehearsal, and documentation stop arriving as surprises. A plan outside its own pessimistic bound gets escalated rather than stretched | A business case or a DESIGN option that needs its cost priced honestly, or the Conductor calling it three times across DEFINE, DESIGN, and BUILD to re-forecast against actuals |
| [hermes-agent.md](hermes-agent.md) | The integration file for a Hermes-style self-hosted personal agent: a routing table that sends each Hermes task type to a tier in [routing/](../routing/README.md) and to the template that holds its output, plus the invariants a personal agent must keep (human approval before anything leaves, no invented claims, the approval queue and never the outbox) | A Hermes deployment doing product-management work, so its artifacts land in these templates and its model calls ride these tiers instead of a hardcoded model name |

Twelve files are a team only once something settles how they work together, and that is [agents/TEAM.md](TEAM.md). It names a lead agent for each stage, with the supporting agents beside it and the human who owns that stage's gate, so two roles never quietly cover the same ground. It fixes the handoff packet every agent hands the next, whether the next reader is another agent or a person, so the artifact in the workspace is never the only record of how it got there. And it sets a four-rung escalation ladder, from a missing input another agent owns up to a deadlocked decision, each rung naming who picks it up next. One rule closes all of it: no agent signs a gate, however confident its recommendation, because a recommendation is a line in a handoff packet and a signature belongs to the named human on the sign-off table.

The Conductor is deliberately not in this list. It is a skill, at [skills/conductor/SKILL.md](../skills/conductor/SKILL.md), because it is a procedure for running the loop rather than a role that produces one artifact. What it does with this directory is hand off: when a question bank routes to research, drafting, a premortem, a gap check, or a red team, the Conductor spawns that role with the accepted answers as its input, then treats what comes back as a draft rather than as evidence.

Two rules apply to every file here, from the gate rules in [AGENTS.md](../AGENTS.md). No role invents a number, a name, a citation, or a quote to make a field look finished, because a plausible fabrication is the one output this system exists to prevent. And no role signs a gate; it verifies and reports, and a named human in [os/STAGE-GATES.md](../os/STAGE-GATES.md) signs.
