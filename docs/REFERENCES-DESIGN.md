# References: design layer

This is the single source and licence register for the design layer (the `knowledge/design/`, `frameworks/design/`, `templates/architecture/`, `templates/ai/ai-interaction-spec.md`, `templates/definition/ui-state-inventory.md`, `templates/definition/ux-writing-guide.md`, and `skills/design-review/` files, plus their filled examples). It replaces the source register that an earlier draft placed in `knowledge/design/README.md` and the per-card licence notes that used to sit inside individual cards. A knowledge card's Reading section now names a source and its reuse class; this file is where that class is defined and evidenced.

## How to read this register

This repository (product-manager-OS) is licensed MIT. That licence covers this repository's own text; it says nothing about the licence terms of anything the design layer studied, and those terms vary row by row below.

Every row in the two tables states a reuse class, chosen from five:

- **Adapt with notice.** The source's own licence permits copying and modifying its text, provided the required notice or attribution travels with the copy. A design-layer file may restate or lightly edit such text as long as the attribution the source requires is present.
- **Paraphrase with attribution.** The design layer may restate the idea in its own words and must name the source and link it. The source's original wording is not copied, because its licence forbids that, is unclear on it, or the material is prose rather than data.
- **Cite only.** The design layer may name the source, link it, and describe in general terms what it says, but may not restate its structure, its wording, or its specific numbers as though they were independently derived. Used for all-rights-reserved commentary and for sources whose reuse terms are unverified.
- **Link only.** The design layer may point a reader at the source but takes nothing from its content into a knowledge card, worksheet, or template, beyond naming that it exists.
- **Never.** The source is excluded from the design layer entirely: no adaptation, no paraphrase, no citation of its specific text as a design-layer claim. The row exists to record why it was excluded, since that is itself a licence-hygiene lesson.

The licence recorded for a source is the licence found in the source's own LICENSE, COPYING, or equivalent file (or, for a site, its published terms page), not a badge, a shield.io image, or a README's unverified claim. Where a source carries no findable licence file or terms page, this register says so and defaults to "all rights reserved," which is the safe assumption for unlicensed creative and prose work.

This register is a research and citation aid maintained by one product-management repository. It is not legal advice, and a licence read here should be re-verified against the primary source before it is relied on for anything beyond the design layer's own paraphrase-and-cite practice.

### Two licence-hygiene lessons

These are recorded as rows in their own right, because the lesson is the useful output and prose would bury it.

| Lesson | What happened | What it means for this register |
|---|---|---|
| A README's licence claim is not evidence | Akira's README states "GNU GPLv3 / Creative Commons BY-SA." The repository's `COPYING` file contains the full GPLv3 text and nothing else; no CC BY-SA text exists anywhere in the tree | Read the licence file, never the README's summary of it. A row in this register records the licence as found in the file, and a mismatch between the two is itself worth recording, as it is here |
| Terms can change by version and by path in the same repository | intro.js is AGPL-3.0-or-commercial from v2.0.0 onward, needs no commercial licence before v2.0.0, and carries a separately MIT-licensed example subdirectory (`example/bootstrap/v3`) inside the same tree | A single "the repository is licensed X" line is not enough when a repository's history or its subdirectories carry different terms. Check the commit actually read and the specific path actually used, not only the top-level licence badge |

## Adding a source

1. Fetch it with `hyperresearch fetch "<url>" --tag design-system -j` rather than any other tool, so the note lands in the vault with the untrusted-content wrapper this project's `CLAUDE.md` describes.
2. Find and read the source's own licence file or terms page, not a badge or a README's summary of it. Record the licence exactly as that file states it.
3. Decide the reuse class from the five defined above, based on what that licence actually permits, and write the attribution string the class requires.
4. Add one row to the matching table in this file (a new repository row under Studied repositories, or a new family row, or a new row inside an existing family, under Research-lane sources) before citing the source anywhere else in the design layer. A knowledge card's Reading section then names the source and points to its row here rather than repeating the licence text.
